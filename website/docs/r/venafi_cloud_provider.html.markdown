# Resource: venafi_cloud_provider

Manages a Cloud Provider: the connection CyberArk Certificate Manager, SaaS or Palo Alto Networks Next-Gen Trust Security
(NGTS) uses to reach an AWS, Azure or GCP account. Cloud Keystores are created on top of a Cloud Provider with the
[venafi_cloud_keystore](./venafi_cloud_keystore.html.markdown) resource, once the Cloud Provider has been validated
with the [venafi_cloud_provider_validation](./venafi_cloud_provider_validation.html.markdown) resource.

## Example Usage

```hcl
# AWS, on CyberArk Certificate Manager, SaaS, which requires an owning team
resource "venafi_cloud_provider" "aws_example" {
  name = "Production AWS"
  type = "AWS"
  team = "Cloud Admins"

  aws {
    account_id = "123456789012"
    role       = "venafi-cloud-provider"
  }
}

# Azure
resource "venafi_cloud_provider" "azure_example" {
  name = "Production Azure"
  type = "AZURE"

  azure {
    application_id = "c3b2a1d0-0000-0000-0000-000000000000"
    directory_id   = "f0e1d2c3-0000-0000-0000-000000000000"
    secret         = var.azure_client_secret
  }
}

# GCP
resource "venafi_cloud_provider" "gcp_example" {
  name = "Production GCP"
  type = "GCP"

  gcp {
    service_account_email = "venafi@my-project.iam.gserviceaccount.com"
    authorization_method  = "VENAFI_GENERATED_KEY"
  }
}
```

## Argument Reference

* `name` - (Required, string) Name of the Cloud Provider.
* `type` - (Required, string) Type of the Cloud Provider: `AWS`, `AZURE` or `GCP`. Changing it creates a new Cloud Provider.
* `team` - (Optional, string) Name or ID of the team that owns the Cloud Provider. Required for CyberArk Certificate Manager, SaaS. Palo Alto Networks Next-Gen Trust Security (NGTS) only accepts a team ID.
* `aws` - (Optional, block) Configuration of an AWS Cloud Provider. Required when `type` is `AWS`, and not allowed otherwise.
  * `account_id` - (Required, string) AWS account ID. Changing it creates a new Cloud Provider.
  * `role` - (Required, string) Name of the AWS IAM role the platform assumes.
* `azure` - (Optional, block) Configuration of an Azure Cloud Provider. Required when `type` is `AZURE`, and not allowed otherwise.
  * `application_id` - (Required, string) Azure application (client) ID.
  * `directory_id` - (Required, string) Azure directory (tenant) ID.
  * `secret` - (Required, string, sensitive) Azure application client secret.
* `gcp` - (Optional, block) Configuration of a GCP Cloud Provider. Required when `type` is `GCP`, and not allowed otherwise.
  * `service_account_email` - (Required, string) Email of the GCP service account. Changing it creates a new Cloud Provider.
  * `authorization_method` - (Optional, string) How the platform authenticates to GCP: `VENAFI_GENERATED_KEY` or `WORKLOAD_IDENTITY_FEDERATION`. Defaults to the platform's choice.
  * `project_number` - (Optional, string) GCP project number. Used with workload identity federation.
  * `workload_identity_pool_id` - (Optional, string) GCP workload identity pool ID. Used with workload identity federation.
  * `workload_identity_pool_provider_id` - (Optional, string) GCP workload identity pool provider ID. Used with workload identity federation.

## Attribute Reference

This resource exports the following attributes in addition to the arguments above:

* `id` - The ID of the Cloud Provider.
* `status` - Validation status of the Cloud Provider: `VALIDATED` or `NOT_VALIDATED`.
* `status_details` - Details of the validation status, if any.
* `keystores_count` - Number of Cloud Keystores that use the Cloud Provider.
* `aws.0.external_id` - External ID generated by the platform, to use in the trust policy of the AWS IAM role.
* `gcp.0.public_key` - Public key generated by the platform for the `VENAFI_GENERATED_KEY` authorization method, to upload to the GCP service account.
* `gcp.0.issuer_url` - OIDC issuer URL of the platform, for workload identity federation.

## Import

Using `terraform import`, import a Cloud Provider using its ID. For example:

```console
terraform import venafi_cloud_provider.example 2155bd32-2234-22ac-7cfd-ff1198845aa2
```

The `team` and the Azure `secret` are not read back from the platform. After importing an Azure Cloud Provider, the first
apply sends the configured secret to the platform, which sets the Cloud Provider back to `NOT_VALIDATED`.
